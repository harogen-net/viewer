## 1. 動機

スライドの有効 / 無効はよく触る操作なのに、現状は **1 枚ずつか全部か**の二択しかない。

- 1 枚ずつ: サムネ左下のチェックボックス、または右クリック →「有効化 / 無効化」
- 全部: 右クリック →「全有効化 / 全無効化」「このスライドのみ有効化」

「この辺の塊を一時的に外す」がやりにくい。加えて、無効化したスライドは暗転するため、
戻すための的が見つけにくいという問題もあった（暗転範囲は 2026-08-24 に絵柄と下地だけへ
限定済み。コミット `a38f74bc`）。

そこで「クリックするだけで有効 / 無効が切り替わる」状態を用意し、その間は他の変更を
一切させないことで、雑に速く切り替えられるようにする。

## 2. 位置づけと命名

**一覧モードのサブ状態**とする。モードの軸（[mode-spec.md](mode-spec.md) §1 の軸 A / B / C）は
増やさない。編集モードでは使わない。

| | 呼び方 | コード上の表現 |
| --- | --- | --- |
| 日本語 | **一括切替モード** | `bulkToggleMode` |

命名は仮。定数 1 つと mode-spec の 1 行だけなので改名は容易。

### 「シーン編集モード」を採らなかった理由

当初この名前が候補に挙がったが、以下の理由で外した。**再提案されたときのために残す。**

1. **「編集モード」は軸 B の正式名称**。mode-spec §1 は「軸 A と軸 B で『編集』の語を二重に
   使わない」と定めており、過去に `ViewerMode.EDIT` という命名が軸 B の編集モードと衝突して
   条件を誤解し、実装をやり直した事故が記録されている。同じ罠になる。
2. **やっていることが編集ではない**。`disabled` フラグを反転させているだけで、シーンという
   実体も構造の編集もない。
3. **シーン（スライドの上位階層）は導入しないと決めた直後**（付録 A）。名前を先に使うと、
   後で本当にシーンを入れるときに埋まっている。

## 3. 確定仕様

| 項目 | 内容 |
| --- | --- |
| 突入 | 一覧の右上に Switch を置く |
| 退出 | 同じ Switch。Esc も受ける |
| クリック | **スライド本体のクリックで `disabled` をトグル**。選択（`selectedIndex`）は動かさない |
| 履歴 | 突入時にスナップショットを取り、クリックは履歴を積まずに適用、**退出時に 1 件だけ記録**。変化がなければ記録しない |
| PC のサムネ表示 | 有効チェックボックスのみ残す |
| スマホのサムネ表示 | チェックボックスも出さない。**暗転のみ**（状態はそれで読む） |
| スマホの画面下部 | 再生設定バー（`SlidePlaybackPanel`）もモード中は隠す |
| 状態の置き場 | 新規の小さな store。document データではないので history には乗せない |

### モード中に禁止する操作

「それ以外の変更（編集・削除・伸縮・結合）は行えない」の実体。

| 操作 | 抑止する場所 |
| --- | --- |
| 編集 / 削除 / 複製ボタン | `src/components/slide/SlideThumbView.tsx` |
| 結合矢印 | 同 |
| 伸縮（表示尺）ハンドル | 同 |
| ダブルクリック → 編集モードへ | `src/components/panels/SlideListPanel.tsx` |
| 並べ替え（dnd-kit） | 同 / `src/components/slide/SortableSlideThumb.tsx` |
| 右クリックメニュー | `src/components/panels/SlideListContextMenu.tsx`（モード中は全面オフ） |
| undo / redo | `src/hooks/useShellKeyboard.ts`（Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y）と `src/components/panels/EditToolbar.tsx` のボタン |

undo / redo を止める理由: モード中に undo が走ると、突入時のスナップショットと実状態が
ずれ、退出時の一括記録が意図しない差分を 1 件にまとめてしまう。抜けてからやり直させる。

## 4. 実装方針（既存機構に乗る）

新しい仕組みはほぼ要らない。

**履歴の一括記録** — テキスト入力の確定と同じ手口が `src/hooks/useDocumentMutation.ts` に既にある。

- 突入時: `snapshot()`
- クリックごと: `applySlideChangeLive(...)`（履歴を積まない。`modified` は常に true になる）
- 退出時: `recordHistory("...", before)`

`recordHistory` は「`slides` 参照が同一なら記録しない」+ `refreshModified()` を実装済み。

※ この見立ては半分外れていた。実装メモ 4 を参照。

**コントロールの抑止** — `SlideThumbView` には既に編集コントロールを一括で隠す prop 経路が
あり（現状は `mobileMode` という名前）、そこへ乗せられる。名前が実態とずれるので
`editControls: boolean` 等への改名を検討する。dnd-kit も「スマホは dnd-kit を通さない」分岐が
既にあるので同様。

**書込権限** — `setSlideDisabled` は既に `WriteCapability.SLIDE_PLAYBACK` なので、
スマホモードでもそのまま通る。gate の変更は不要。

## 6. テスト観点

- モード中はスライドクリックで `disabled` が反転し、`selectedIndex` は動かない
- モード中に 3 枚触って抜けると履歴が **1 件**（3 件ではない）
- 触って元に戻して抜けたら履歴 0 件、`modified` も立たない
- モード中は編集 / 削除 / 複製 / 結合 / 尺 / 並べ替え / 右クリック / undo が効かない
- PC はチェックボックスあり、スマホはなし
- スマホでは `SlidePlaybackPanel` が隠れる
- Esc で抜ける

## 付録 A: シーン（スライドの上位階層）を導入しなかった経緯

本モードの前に「slide の上位に scene を作り、scene 単位で有効 / 無効にする」案を検討し、
**見送った**。同じ話が再燃したときのために結論だけ残す。

### 実測した波及

| 依存箇所 | 規模 |
| --- | --- |
| `src/utils/slideOps.ts` の純関数 | 17 個すべてが `SlideState` 入出力 |
| flat index（`selectedIndex` / `editingIndex`）を使うファイル | 25 ファイル |
| history snapshot | `before` / `after` が `SlideState` そのまま |
| `!disabled` でフィルタしている箇所 | 10 箇所 |
| 保存形式 | `slideData` は flat 配列。レガシーと byte-equal を意図的に維持している |

### 結論

- **`slides: Slide[]` を `scenes: Scene[]` にネストするのが最も高い**。あらゆる index が
  (scene, slide) の組になり、上記 17 + 25 が全滅する。
- 安い代案は **配列を flat に保ち、所属だけ持たせる**（`Slide.sceneId` + 順序付き `Scene[]`）。
  17 ops と 25 ファイルの index 体系が無傷で、保存も `sceneData` の追加互換に収まる
  （scene が 1 つだけなら出力しない = 既存ファイルと byte-equal を維持）。
- 最も重いのは UI。ただし scene を「連続スライドのグループ」に限れば**入れ子 D&D は不要**で、
  境界をまたいだドロップで所属が変わる（正規化を mutation の choke point 1 箇所に置く）。
- 最も事故りやすいのは `!disabled` の 10 箇所を「scene も見た有効判定」へ置換する工程。
  1 箇所漏らすと「無効シーンなのに再生 / 書き出しされる」になる。

### 見送った理由

元の動機が「グループ単位で素早く on/off したい」ことだったため、階層を作らずに済む
本モードで足りると判断した。実運用して足りなければ、上記の flat + 所属フィールド方式で
Phase 1（型と純関数）→ 2（有効判定の一元化）→ 4（保存）→ 5（再生 / 書き出し）→ 3（UI）の
順に進める。

## 実装メモ（2026-08-25）

計画どおりに収まったが、書いていなかった点が 3 つ出た。

1. **`applySlideChangeLive` / `recordHistory` に書込権限の引数が無かった。**
   既定が `WriteCapability.FULL` のため、スマホモードでは silent に弾かれてモードが
   一切動かない。第 3 引数（省略時 FULL）を足して `SLIDE_PLAYBACK` を渡すようにした。
2. **文書を差し替えたときの打ち切りが要る。**
   モード中に「開く」「新規」を実行すると、突入時 snapshot が前の文書のものになる。
   そのまま退出すると undo が前の文書を復元してしまうため、`meta` の変化で
   履歴を残さず打ち切る経路（`cancel()`）を用意した。
3. **`EditToolbar` の undo/redo ボタンは対応不要だった。**
   編集モードでしか描画されず、一括切替モードは一覧モード限定なので共存しない。
   キーボードショートカット側（`useShellKeyboard`）だけ止めれば足りる。
4. **「変化が無ければ記録しない」は `recordHistory` 任せにできなかった。**
   §4 で「既存コードで成立する」と書いたが、`recordHistory` の判定は `slides` の
   **参照**一致であり、A を消して A を戻すと中身が同じでも別配列になるため空の履歴が
   1 件積まれる（テストで検出）。退出時に内容で突き合わせてから渡すようにした。
   あわせて、記録しない経路でも `refreshModified()` を呼ぶ必要がある
   （`applySlideChangeLive` が `modified` を無条件に立てるため）。
5. **モード ON でサムネが作り直されるのを避けるため、描画ツリーを組み替えないこと。**
   当初は「D&D 無しの素の一覧」へ branch を切り替えたが、全サムネが unmount → remount され
   canvas の再描画が全枚数で走った。PC 側は DnD 経路のまま `useSortable` の `disabled` で
   並べ替えだけ止める。あわせて canvas 再描画の依存を「絵に効くもの」だけへ絞り、
   1 クリックごとの無駄な再描画も止めた。

サムネ上の非操作ラベル（番号バッジ / 表示尺ラベル）はモード中も残している。
「チェックボックスのみ」の対象は操作できるコントロールと解釈した。
